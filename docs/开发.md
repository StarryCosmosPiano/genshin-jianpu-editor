# 开发与验证

## 环境

- Node.js 20 或更高版本
- Tauri 桌面构建需要 Rust stable 与 Cargo
- 重新生成 JPW ANTLR parser 时需要 JDK
- 浏览器端截图回归使用本机 Microsoft Edge

首次安装使用锁定依赖：

```bash
npm ci
```

## 启动与构建

```bash
npm run dev          # Vite 开发服务器
npm run web          # Windows 本地网页端：127.0.0.1:1420 并自动打开
npm run build        # TypeScript 严格检查 + Vite 生产构建
npx tsc --noEmit     # 只检查 src/
npm run tauri dev    # Tauri 桌面应用
cd src-tauri && cargo check
```

根目录 `*-check.ts` 不在 `tsconfig.json` 的 `include` 中，由对应 npm 命令通过 esbuild 打包后执行。

## 回归层级

### 快速核心回归

```bash
npm run check:core
```

依次执行：

- `check:format`：共享扩展名注册、打开/保存信息、JPW/TXT 解析边界、多个 Voice 和乱序声部源码映射
- `check:horizontal`：节奏列、小节宽度、目标小节数和贪心装行
- `check:piano`：钢琴双行、总谱、MusicXML、花括号、小节线和 MIDI 结构
- `check:midi`：SMF 解析、量化、三连音、手部、多轨和速度
- `check:staff:unit`：当前 Score 的五线谱只读投影、音符版本引用、音高拼写、真实时值和跨小节拆分、补休止及延音关系；随 `check:core` 运行
- `check:slashscore`：键盘谱/数字谱、时值、休止、U+2063 和多声部往返
- `check:source-mapping`：同音重复、琶音、局部换调、多声部三连音及长谱的音符到源码映射
- `check:incremental-layout`：模型快照的精确失效与新对象地址重绑；增量/完整排版对比，涵盖改音、时值、跨小节延音、三连音、页高/宽、样式、增删小节、调号、速度及失败后恢复
- `check:input:unit`：输入编辑纯逻辑、精确换调、三连音空格与延音、文档设置撤销和谱末光标边界；包含 `check:triplet` 的附点音去点创建、正拍混合元数据、第三格编辑及 TXT 往返，同小节独立组及重叠长短组的元数据隔离；跨拍长三连音的按拍输出、纯正文及旧版注解兼容回归
- `check:triplet:overlap`（随 `check:triplet` 运行）：`triplet-delimiter-check.ts` 核对同功能多种括号的规范输出及未改拍组原文保留；`overlapping-tuplet-check.ts` 核对不同声部重叠三连音分别恢复真实起点/时值、同显示格异时音不合成和弦；`overlapping-mordent-check.ts` 核对共享三连音内另一声部波音的 `[ABA]` 正文、主音独占普通时值和重复保存重载。同声部三连音成员仍不能添加波音。

### 三连音往返修复专项

`npm run check:triplet:repair` 是 TXT 三连音与并行声部的集中门禁，已接入 `check:triplet` 与 `check:core`。根目录专项脚本只使用仓库内置样本和 `fixtures/triplet-*.json`，不依赖本机私有 `artifacts/` 数据：

- `triplet-roundtrip-repair-check.ts`：读取 `fixtures/triplet-roundtrip-repairs.json` 和 `fixtures/triplet-random-repairs.json`，在纯模型中核对编辑前控制保存、创建后多次保存重读、成员填入及播放时间线。
- `triplet-sustain-check.ts`：内嵌单声部 case29、两声部 R29/R292，核对普通/草稿保存、隐藏休止、跨小节延音、并行全音符与三连音末音后的静音。
- `triplet-diagnostic-check.ts`：核对拍切片、相邻三连音与非法时值后缀的结构化诊断。
- `triplet-overlap-dotted-check.ts`：覆盖不同声部错位、包含、重叠和附点组合，失败时保留逐例报告供定位。
- `triplet-roundtrip-repair-check.mjs`：构建后驱动本机 Edge，在真实编辑器执行内置修复样本的菜单/键盘操作和重复保存重载；可单独用 `npm run build && node triplet-roundtrip-repair-check.mjs` 运行。

专项命令执行纯模型、延音、诊断与重叠附点回归；浏览器重放已接入 `check:browser`。修改 `src/slashscore/`、三连音编辑或相关时间线时运行这些检查，并保留 `npm run check:slashscore` 和现有 `check:triplet` 门禁。

### 整体内容缩放、音乐密度与页面水印

“排版→纸张与字号→整体内容缩放”滑块范围25%–200%，默认100%。保持所选纸张不变，标题、署名、歌词、速度、乐器名和全部音乐记号共同缩放并重新装行、分页，打印和页面导出使用这个比例。基础字号仍保存原始值，比例不会反复累乘；底部屏幕查看缩放独立。相关回归可单独运行 `npm run check:content-scale`。

排版设置中的“乐谱本体大小”默认约70.7%，简谱与五线谱共享此设置。它改变音乐字形测量、间距和装行，在A4页上容纳更多内容；标题、速度、调号说明、乐器名和歌词保留独立字号，底部预览缩放不参与此排版设置。简谱默认每行目标6小节，实际仍服从最小宽度和显式换行。

页面导出按当前活动谱区提供PNG/PDF，简谱另提供矢量PPTX。选择格式后进入水印窗口，可开关水印、编辑文字和实时查看实际谱页；默认不透明度10%、每页7枚斜水印，中央完整、边缘可裁。取消不保存偏好，水印只写入导出副本。五线谱通过独立页面渲染接口导出全部页面，不依赖当前挂载的虚拟页，也不带入选择或播放高亮。

### 界面组织与设置

主界面名称为“原琴助手编辑器”，保留 Tauri identifier、文件关联、旧存储键和文档格式。
`src/bootstrap/workspace.ts` 负责菜单、工具栏、文本面板拖动及状态栏；`src/ui/theme.ts` 负责主题，
`src/ui/inspector.ts` 负责单个悬浮设置窗口与未应用修改提示；`src/ui/floating-window.ts` 管理拖动、缩放、边界与独立位置存储。新增组织逻辑不放进 App 的编辑算法。

`src/ui/app-dialog.ts` 统一异步输入、确认和消息提示，替代 `window.prompt/confirm/alert`；文件选择与打印仍走原平台入口。
输入窗口复用 `FloatingWindow` 的可选尺寸、居中与不持久化配置；乐谱/排版窗口的默认尺寸及存储规则不变。
同一时间只显示一个输入提示，背景暂时 `inert`，关闭恢复焦点及原状态；Enter/Escape、Tab 焦点循环和多行 Ctrl/Cmd+Enter 在窗口内处理。
输入通过校验并确认后才走原编辑事务；取消和文档替换不提交，跨 await 的模型修改同时检查 Score 身份。
设置点击背景时异步提供应用/放弃/继续编辑三种结果，渐快/渐慢的速度与终点合并填写。拖动/缩放不解析或序列化乐谱。

`editor/score-header.ts` 组织谱头输入，App 仅协调原文档事务；`editor:header-changed` 用局部字段同步已打开的乐谱设置，不覆盖其他分类草稿。
`editor/keyboard-note.ts` 提供三排琴键映射；直接改音只替换活动音符的源码跨度，保留时值、和弦其他音和隐形声部标记。
`ui/details-scroll-retention.ts` 在分类折叠前预留空间，完成展开/折叠后恢复原 scrollTop；空间只随上滚回收，关闭面板解除监听。
花括号新默认宽0.35×、粗3.2px，滑条分别为0.1–2×、0.1–5px；旧版更大的自定义值仍由归一化保留。延音/圆滑线默认厚度4→3.2，几何算法不变。

主题存储在 `jpeditor.ui.theme`，默认 `system`；新版布局状态沿用 `jpeditor-render-settings`，
增加 `workspaceLayoutVersion: 2`、`codePaneWidth`、`beatPositionFormat`、`showTextOnStartup` 和 `restoreLastFileOnStartup`。
旧版迁移默认左侧展开，启动默认载入内置键盘 TXT 示例；可在设置选择启动时隐藏文本或恢复上次文件。宽度/左右偏好持久化。以上设置不写入乐谱。

排版草稿使用 `App.setEngravingPreview`：只针对当前 Score 重新排版，保留 `.Layout` 断行设置，
不解析、不序列化、不写存储。200ms 连续修改只预览最后一份草稿；应用同步提交并保存，取消清除待执行预览后恢复。
`setEngravingStyle` 提交已保存值，文档语义设置仍通过原有撤销事务提交。
`ui/layout-preview-pane.ts` 在左栏切换文本/样张，保留 CodeMirror 实例；排版关闭后恢复原文。
`editor/shortcuts.ts` 定义与缓存场景快捷键，`ui/shortcut-settings.ts` 提供独立编辑窗口，偏好位于 `jpeditor.ui.shortcuts.v1`。
花括号使用 `layout/brace.ts` 的填充路径；`EngravingStyle.connectBarlines` 默认 false，由设置控制钢琴/总谱跨行连接。
打谱进入位置由 `input-entry.ts` 解析，`ScoreInputSession` 支持已启用但 cursor 为 null 的等待状态。

### 五线谱只读预览（0.4.0 本地开发，2026-09-25）

`src/staff-preview/` 直接读取已成功排版的简谱 `Score`，投影成独立模型并用 VexFlow 5 的 SVG 后端绘制。
不经过 MusicXML 导出再导入，不写回音高、时值、源文本或撤销历史；与 `src/mixed/` 的独立 MusicXML 混排模型分开。
`model.ts` 处理音高拼写、声部时间线、补休止、三连音和跨小节拆分；`renderer.ts` 处理五线谱排版、系统模板缓存和 SVG，字体、导航索引及 SVG 辅助分别在 `renderer-fonts.ts`、`renderer-navigation.ts`、`renderer-svg.ts`；
`identity.ts`、`types.ts` 保存 `Note` 与 `{revision,id}` 引用；`controller.ts` 组织视图、导航、虚拟页与异步任务；App 仅提供模型、选择和播放桥接。

启动仍显示简谱；首次开启五线谱使用对照，之后记住五线谱/对照偏好。谱区宽度不足 760px 时，对照临时切成单谱，恢复宽度再还原。
左右分栏比例保存在 `staff-preview-divider`，预览偏好保存在 `staff-preview-view`；文本面板保持原独立行为。
两个谱区分别滚动、分页和缩放，底部标明活动对象；首次生成适应五线谱可用宽度。关闭释放预览文档和已挂载页面，恢复简谱可见位置。

选择按当前版本的 `Note` 身份双向同步简谱、五线谱及文本；Ctrl/Cmd 点击切换单项。同音和弦、倚音和视觉续音不依靠音高字符串猜测。
五线谱获得焦点后隔离改音、N、Delete、方向键和数字编辑；定位另一侧不抢焦点。普通模式从五线谱主选择开始播放，打谱模式中的空格仍不播放。
播放事件沿用原播放器和反复 pass，两侧高亮；选择为浅紫，播放为金色，两者重合保留紫色音头并加金色光圈。
手动滚轮、触屏、拖动滚动条或翻页只暂停该侧跟随，可用“恢复跟随”重启；新一轮播放恢复跟随，隐藏谱区不滚动，已可见音符不反复跳页。

VexFlow/渲染模块只在开启预览时动态加载，关闭状态不生成五线谱。更新按 200ms 合并，旧任务取消，并在异步结果接纳时复核 revision 和模型当前状态。
关闭时仅维护模型失效版本，不发送五线谱选区、播放和模型通知；开启时再读取当前选择与播放状态，避免给普通编辑增加后台更新。
锁定、待解析或失败期间，旧预览保留但不能选音；成功后才重新绑定引用。重排优先保留选音/播放的音乐位置，否则使用可见首音及其视口偏移。
页面只挂载可见范围及前后各一页的 SVG，系统几何模板按内容缓存；新快照即使复用图形也必须重新绑定当前 Note，不能沿用旧模型地址。
模板缓存同时包含谱行边界的调拍号、跳房子和远端连线信息，防止跨谱行改动沿用旧图形；打开另一文档立即释放旧页面和音乐位置锚点。
可访问状态用 `#staff-pane[data-staff-revision]` 表示最后成功版本，`aria-busy` 表示等待/生成；回归应等版本匹配且忙碌状态结束，不依赖中文提示。

当前入口仅支持单行与钢琴双行；多乐器总谱、识别视图和混排视图禁用并显示原因。支持音符/休止、和弦、谱号调拍、附点、三连音、延音/圆滑线、反复/房子、歌词、速度/文字及已映射装饰音。
这是普通简谱模型的阅读投影，不承诺复现原始 MusicXML 的出版布局，也不新增五线谱编辑或专门导出；踏板、力度渐变等未投影的记号仍以原模型和原播放/导出为准。
无法精确表示的时值（当前最小 128 分音符）拒绝生成并保留上次预览；未映射装饰音、过密小节等显示诊断，不能静默改写原谱。
单小节超出纸张可用宽度时，按自然宽度绘制后整体缩小该谱行，并提示比例，保证尾部音符不会被纸张边缘裁掉；非二进制拍长的空隙保持精确时间间隔并提示未补写休止符。


## GitHub 发布

本项目的发布仓库为 `StarryCosmosPiano/genshin-jianpu-editor`，所有 `gh` 发布和工作流命令显式指定
`--repo StarryCosmosPiano/genshin-jianpu-editor`，避免被 `upstream` 远程影响。

从应用版本 0.4.0 起，使用 `yuanqin-v<版本>` 标签；仓库仍保留上游同名 `v0.4.x` 等历史标签，不移动或覆盖它们。
发布前先查询远端标签，确认新标签尚不存在；在验证完成的提交上创建并推送标签，使用
`gh release create <标签> --verify-tag --notes-file <说明文件> --repo StarryCosmosPiano/genshin-jianpu-editor`
创建发布。应用的 package、npm 锁文件、Tauri 配置、Cargo 包和锁文件版本保持一致。

`main` 推送部署在线版；Release 发布触发 Windows x64 和 macOS Apple Silicon 安装包构建。
检查工作流的提交与发布标签一致，并确认两个安装包均上传成功。核心回归必须只依赖已提交文件或内置样本；
本机私有曲谱不能成为 CI 必需条件。现有 `scripts/release.sh` 使用旧标签规则和 macOS 命令，不能直接用于此发布流程。

用户明确要求更新同一应用版本时，保留现有 Release，先完成验证并推送 `main`；仅更新该应用的 `yuanqin-v<版本>` 标签，并用远端旧标签对象的 `--force-with-lease` 防止覆盖他人的更新。随后手动运行 `Build` 工作流并传入 `release_tag`，工作流校验标签与应用版本一致、查找现有 Release，再构建并替换对应安装包；不会重新创建发布或覆盖说明。手动输入留空仍仅部署 Pages。安装包统一使用 `Yuanqin.Editor_[version]_[arch][setup][ext]` 文件名，保持同版本下载地址不变。

## 修改约定

- 工作区可能包含用户未提交改动，禁止用 `git reset --hard` 或覆盖无关文件。
- 文件按单个文件依次保存，避免一次机械重写多个核心文件。
- `src/jpword/parser/` 是生成代码，修改 `Jpwabc.g4` 后重新生成。
- 排版测量必须继续使用 `common/measure.ts` 的 SVG 测量路径。
- 不在源码中写 SMuFL 字面 PUA 字符。
- 本地 `src/assets/soundfonts/*.sf2`、`testdata/` 和用户曲目由 Git 忽略，不进入发行包。

项目模块和数据流见 [技术栈.md](技术栈.md)，当前功能状态见 [进度.md](进度.md)。所有简谱行为及其稳定逻辑 ID、实现入口和最低回归集中登记在 [简谱逻辑总表.md](简谱逻辑总表.md)；行为改动必须同步更新对应行，便于用 Git diff 查看本次改了哪些逻辑。

悬浮窗口偏好保存为 `jpeditor:inspector-window:score:v1` 与 `jpeditor:inspector-window:layout:v1`，与乐谱及排版参数分开。
谱面选音两主题统一使用 `--score-selection-ink: #A98DD4`；文本保持 `--selection-ink: #EFBB52`，按钮仍使用原品牌金色；关联文本的实底金色和深色字只作用于临时选区，取消后恢复语法/声部色。
