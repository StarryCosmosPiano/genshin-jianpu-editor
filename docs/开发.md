# 开发与验证

## 环境

- Node.js 20 或更高版本
- Tauri 桌面构建需要 Rust stable 与 Cargo
- 重新生成 JPW ANTLR parser 时需要 JDK
- 浏览器端截图回归使用本机 Microsoft Edge

首次安装使用锁定依赖：

```bash
npm ci
```

## 启动与构建

```bash
npm run dev          # Vite 开发服务器
npm run web          # Windows 本地网页端：127.0.0.1:1420 并自动打开
npm run build        # TypeScript 严格检查 + Vite 生产构建
npx tsc --noEmit     # 只检查 src/
npm run tauri dev    # Tauri 桌面应用
cd src-tauri && cargo check
```

根目录 `*-check.ts` 不在 `tsconfig.json` 的 `include` 中，由对应 npm 命令通过 esbuild 打包后执行。

## 回归层级

### 手机与平板触屏工作区（2026-10-18）

工作区模式独立于乐谱格式：自动、手机、平板、桌面。自动模式在启动时读取触摸能力，768px以下使用手机布局；外接鼠标或键盘不改变已选模式。可用高度低于500px且宽度至少600px时把操作盘放到右侧，窄分屏保留可折叠底部盘，对照要求两侧各有420px（含8px分隔线共848px）。缩放只变更查看比例，不改变打印页面排版。

`App.executeScoreCommand()` / `getScoreEditorState()` 是屏幕操作盘、菜单和键盘共用的编辑边界。UI不直接写Score，也不派发伪造键盘事件。单点选择/定位，数字键或确认写入，默认不前进；和弦追加使用独立待输入目标。手势由 `touch-gesture-state.ts` 统一处理，第二根手指、取消及拖动都撤销待点击。五线谱保留实体数字键设置时值的行为，屏幕数字则按当地调号输入音级。

触屏保存先使用浏览器选址能力，无该能力时生成完成后再次点击系统分享或下载副本。分享取消不触发下载，分享和本机草稿不标记外部原文件已经覆盖。IndexedDB草稿在500ms后写入原文、格式及必要选项，后台补写；无法解析的原文也能恢复。图片/PDF有文件、相册和拍照入口，移动PDF选择页码后逐页识别并释放中间位图，多页结果进入普通编辑谱。

触屏简谱保留全部页面占位，只挂载可见页及相邻页；离屏导出使用独立DOM引用。首屏不等待SF2，首次播放/音源设置按需读取；播放和试听复用音频设备与解码音源，最多8组重叠试听，切后台或音频中断后需用户再次启动。Service Worker更新不刷新已挂载的编辑会话。

```bash
npm run check:mobile:unit  # 命令、和弦目标、手势、文件与草稿
npm run check:mobile       # 构建后触屏布局/编辑/文件/长谱与实际音源
```

专项输出在 `artifacts/mobile-*`，端到端脚本可通过 `MOBILE_TEST_URL` 接入开发服务器。测试矩阵包括320/390px手机、低高度横屏、768/1024px平板、分屏及软键盘可视视口。桌面 `interaction-mode-check.mjs` 明确使用桌面工作区，保留原键鼠/长按回归；独立移动专项验证新手势。

本机Edge模拟不能证明iOS Safari和Android Chrome真机通过。发布前需在真机完成新建→点选定位→输入→和弦→多选→记号→撤销→保存/分享→重开，另核对分享取消、权限失败、后台恢复、横竖屏、系统键盘、外接键盘/笔。网页版与主屏幕启动使用同一实现，本轮没有原生移动App或完整离线承诺。

### 导出显示选项与五线谱样式（2026-10-18）

PNG、ZIP 和普通 Score 的 PDF 导出窗口可直接选择简谱或五线谱，不要求先切换活动谱区。简谱支持当前显示、数字简谱和键盘字母；简谱矢量 PPTX 使用相同显示选项。颜色标记每次默认关闭，开启后使用当前声部配色，不带入选择或播放颜色。五线谱禁用数字/字母选项，暂不提供矢量 PPTX。切换选项使用独立 Score 克隆及重新排版后的页面，确认后写入同一组页面；页数、翻页和 ZIP 选项随结果更新，不修改文档、音高、显示偏好或屏幕 SVG。

水印 1–15 档控制间距，默认第7档；按页面短边计算完整网格，保留中心水印及上下、左右对称点，不截取前若干个位置。横竖方向、页面尺寸、SVG 和矢量 PPTX 共用位置算法。水印设置保存至 v2，兼容读取旧版文字、透明度和滑杆档位；只有确认导出才保存。

五线谱乐器名只出现在首个系统；速度、渐快等文字从所属五线谱顶线附近开始，按实际文字边界避让符头、符干、符杠、加线、刻度和相邻文字。短延音线根据实际符头间距调整端点与弧高，避免短小竖钩和直接消失；延音线略加粗。加线统一深色并随音乐比例调整长度和笔宽，连接符也随比例缩放。浏览器专项检查缩小、放大、恢复后的几何一致性。

### 琶音成员、同拍多选与选址保存（2026-10-18）

花括号中的琶音保存实际成员，外层和弦不扩大范围。同组成员都在一个谱行时显示局部琶音，包含两行成员时显示跨谱行琶音；一列可包含多个独立组。`Chord.arpeggioPitchGroups` 保留局部成员集合，旧字段继续兼容；跨谱行组使用明确声部及音高。排版按成员实际字形范围和归一化后的横向边界留位，覆盖连接小节线开关及两种间距模式。JPW、TXT、MusicXML 和播放使用同一成员范围。

打谱多选只在真实起音相同时批量移动或改时值，支持同和弦子集及跨声部。普通时值边界逐音跳过，未满的音仍可修改；不兼容的移动整批拒绝。未选音起止时间保持不变，一次操作对应一次撤销。JPW 的 `Annotations.noteTies` 和 TXT 的 `note-tie` 端点保存部分和弦成员延音，同音成员以出现次数区分。提交前重读真实保存文本并比较全谱逐音起止，防止只在预览中正确。

同拍移动合并原列与目标列能共存的记号，无法同时表达的倚音、连奏或颤音设置在修改前拒绝。跨调号移动按目标位置重新拼写，保留实际音高及重复保存后的延音；同调号保留原等音拼写。换调、五线谱及多选改音先捕获琶音成员身份，整批结束再恢复分组，避免中间暂时同音导致串组；最终同音若无法由现有分组格式准确保留成员，则拒绝整次改音并保留原谱。`key-edit-check.ts`、`staff-edit-unit-check.ts`、`multi-input-check.ts` 和 `same-onset-input-check.ts` 覆盖这些边界。

保存与导出先选本地文件或目录，再生成内容并写入，浏览器不回退到下载链接。`Ctrl/Cmd+S` 在文本、谱面、打谱和工具栏焦点下保存当前文档；`Ctrl/Cmd+Shift+S` 另存独立副本，保留正式保存目标及其未保存状态。导出目标与文档保存目标独立。浏览器需提供安全上下文中的文件选址接口；桌面沿用 Tauri 文件对话框。取消选址不编码/写入，流关闭失败不标记成功，多页 PNG 目录中的同名文件先统一确认。

### MIDI 三连音导入（2026-10-17）

MIDI 导入统一记录本次采用的全局及分手三连音，按原始音符身份保留起音位置；TXT 输出复用这一结果，关闭识别时不重新启用。局部已采用的起点优先，拒绝给同一源音符分配另一时刻的全局候选；默认/JPW 模式维持其每声部可写出的量化，避免保存重开时把无分组的分数时值变成普通时值。共享跨手组三连音在启用和弦容器时保留同时发生的声部休止，以免前一音延续到下一成员。普通伴奏与三连音交错时按并行声部输出，合并声部时按实际起音联合细分。必要时自动增加更细的时值符号，保留原有符号单位；MIDI 量化菜单仍为 4–64 分，生成的 TXT 可保留 128 分映射。TXT 内部重建保留已解析的分数节奏，避免再次量化后产生重复起音。

`npm run check:midi:triplet` 运行不依赖用户曲目的合成回归，并随 `check:midi` / `check:core` 运行。先运行上述命令构建检查程序，再使用 `node artifacts/checks/midi-triplet-import-check.mjs "<MIDI路径>"` 追加《从前说 - 原琴 C调完整版》的六处原始 tick 核对；该特定曲目不随源码分发。构建后运行 `node midi-triplet-browser-check.mjs "<MIDI路径>" "<截图目录>"`，在本机 Edge 中验证键盘谱和数字谱导入、实际 SVG、保存及重开，默认将截图与记录写入系统临时目录；其他 Chromium 安装可通过 `BROWSER_EXECUTABLE_PATH` 指定。

### MIDI 起音与三连音编辑（2026-10-17）

MIDI 转文本谱保留全曲首次起音前的真实休止，避免没有前音可延续的前缀时值被回填到首音。首次起音边界每次导出计算一次；保留/隐藏休止两种设置下都保持真实的首音位置，手写文本的合法前缀语义保持原规则。

相邻独立三连音组中的同音仍是两次攻击，旧的组外尾段推断不能跨进下一组误接延音。具有明确续音身份的跨组长音在下一共享 3:2 区间确实包含分数尾段时，保留原组结束边界并补齐后一组首成员；普通完整二分、全音符伴奏不额外拆分。无关位置的音高编辑、撤销、重做、保存和重新打开均应保留其他声部的起止时间和三连音书写结构，不能只检查播放时长或错误提示是否为空。

关闭保留休止后，退出打谱的空位补齐仍把自动生成的跨小节续音作为正在发声的区域；不能在半拍或整小节续音上叠加休止，否则后续 TXT 重读会在小节线上截断原延音。`input-edit-check.ts` 用双声部合成谱覆盖连续两次补齐、双向延音链及键盘/数字 TXT 往返。

`npm run check:midi:leading` 和 `npm run check:midi:edit` 提供自包含回归，并随 `check:midi` / `check:core` 执行。构建专项后，可直接追加实际伴奏 MIDI：

```bash
node artifacts/checks/midi-leading-silence-check.mjs "<伴奏MIDI路径>"
node artifacts/checks/midi-edit-regression-check.mjs "<伴奏MIDI路径>"
```

构建后执行 `node midi-onset-edit-browser-check.mjs "<伴奏MIDI路径>" "<截图目录>"`，使用真实谱面点选、工具栏打谱和键盘输入，覆盖键盘谱/数字谱、保留/隐藏休止，检查第 2 小节改音高和第 95 小节改音高/改为休止、退出编辑、撤销重做及全新会话重开 TXT。逐事件核对未修改声部的音高、起止时间，以及三连音成员和书写时值；默认使用本机 Edge，可通过 `BROWSER_EXECUTABLE_PATH` 指定其他 Chromium。截图和完整断言记录写入传入目录，未指定时写入临时目录。

此次特定曲目断言使用《从前说 - 原琴 C调伴奏 导入用.mid》（PPQ 480、1217 次真实起音）；首 G5 为绝对 1.5–2 拍，第 95 小节相邻 G3 是独立起音。已保存成错误延音的旧 TXT 可能丢失重弹信息，应重新从原 MIDI 导入。

### MIDI 音值组合与长延音（2026-10-17）

三连音成员的一个 `cell` 只决定括号内时值，不能截断源音的真实释放位置。`quantizeHand` 保留量化后的长音尾；`makePart` 将真实三连音成员与分组外普通尾段分别构造，使用原延音链连接，并保留后续真实起音和实际休止。和弦各音释放不同时，超出三连音成员的普通尾段使用所选二进制网格合并释放，避免合并出未分组的分数时值后在 JPW 保存时漂移。

TXT 普通长音与共享三连音相交时，`metricalContinuationStartsWithTuplets` 按已知 3:2 区间分段，`adoptSharedTripletSpelling` 为需要分数时值的声部建立合法成员：例如 `7/3 = 2 + 1/3`、`7/6 = 1/2 + 2/3`。这些是同一源音的延续，不能额外重弹。普通二进制长音不因另一声部有三连音而改成三连音。`applySlashTuplets` 对分组外尾段复用按小节的音值组合，完整四拍延音写成一枚全音符，而不是四个四分音符串联。

三连音注解增加可选 `memberContinuations`，与 `members` 等长的布尔数组表示明确的续音成员；旧文件缺省兼容。导入/乐谱设置窗口须深拷贝保留原有 `annotations` 与 `noteTimingEdits`，避免确认时重写尾注丢掉无控件对应的语义数据；`app-dialog-check.mjs` 提供自包含重新导入回归，实际曲目专项另外核对全新会话。乐谱设置未改动时点击应用按未修改关闭，避免无意义地物化时值覆盖或重写文件。共享攻击列在 TXT 输出时复用，避免重复括号。 三连音源成员匹配保留原事件先后位置，已有独立声部三连音不被新的共享写法覆盖。普通二进制伴奏从共享组退出时，须同时确认原成员不完整且音尾超过成员边界；单成员三连音及完整附点三连音保留。重复保存和键盘/数字互转必须核对完整事件的声部、音高、起音、结束时间及次数，不能只检查音符总数。保留休止与隐藏休止仍遵守现有语义：隐藏休止可由前音填满内部静默，不能拿这种用户选定的填充结果当作 MIDI 原始 note-off。

### 无斜杠文本导入与添加斜杠（2026-10-12）

打开无斜杠 TXT 会先进入“添加斜杠”窗口，也可从“文件→添加斜杠…”粘贴文本。确认补斜杠后进入现有“导入键盘谱 / 数字谱”设置窗，最终确认才替换文档，任何一步取消都保留当前乐谱。两窗右侧均由 `src/editor/slash-score-preview.ts` 独立解析草稿并经 `JinpuPainter` 绘制真实 SVG 简谱，复用 App 已加载字体元数据和排版设置；默认简谱，可切换只读文本谱，第二步显示按目标设置换写后的文本及相同音长的简谱，设置更新保持已选预览方式，未填完拍号时仍可预览原文。导入窗口经 `src/ui/import-dialog.ts` 阻止窗口外点击并禁用背景，不自动取消、不提示保存，明确关闭后恢复背景；MIDI 与 MusicXML 导入同样适用。输入限流刷新、每次只挂载一页、可翻页、窄屏上下排列，关闭时清除待执行刷新与预览 DOM。`src/slashscore/add-slashes.ts` 负责行识别、候选分析和转换，`src/editor/add-slashes-dialog.ts` 管理设置、可编辑原文、折叠结果文本及逐行拍长核对，`App.importBytes` / `App.addSlashes` 编排两步确认。

只从有效谱行提取实际出现的时值符号，初始映射为空，不按 `+/-/=` 或其他符号名字指定固定时值。给定拍号后组合试算 4–64 分的符号时值，优先匹配“一原文行恰好一小节”，需要一行多小节的方案靠后；例如 4/4 的 `QV+-JA+-QF+++++` 包含七个 `+` 和两个 `-`，候选 `+` 八分、`-` 十六分使总长为 4 个四分音符。拍长始终以四分音符为单位。无括号时优先把紧邻字母作为同时和弦，音符自身时值为空；有括号时列出有/无自身时值的候选，不仅凭括号存在就增加基础时值。普通空白默认仅作排版，第二导入窗设置空格时值时同样按固定源音长校验和换写；速度、曲名、说明和纯符号分隔线不参与计算。超过三个不同符号时只枚举前三个，其余需手动指定。

导入初始不猜时值；顶部提示先填写拍号或点击“分析拍号”。导入首次填写有效拍号且尚未手改时值时，按该拍号自动分析并采用一次符号时值候选；此后修改设置只更新预览，采纳其他时值方案须点击候选，手动添加斜杠入口不自动采用。拍号不确定时分子留空，先手动核对原文符号时值，再点击“分析拍号”列出候选及依据；拍号候选只有点击采用后才写入设置，不自动覆盖手工选择。相同总拍长可能对应多个拍号，必须选定拍号才能应用。修改原文只同步实际符号列表、保留仍存在符号的手选时值，并刷新预览；新出现符号保持未指定。已有斜杠谱的导入窗只初始化一次建议拍号，从补斜杠窗传来的拍号及源时值完整保留，不混入默认符号或再次猜拍号。

第一步确认后固定源文本及源 `SlashScoreOptions`。第二步修改目标符号、符号时值或 `division` 时，`reencodeSourceTimedRows` 按固定源音长等长换写，返回 `{ text, options, canImport, warnings, errors }`；例如源 `+` 八分、`-` 十六分，目标点号三十二分时分别写成四点和两点。每次修改均从首步原文重新计算，禁止累计转换或按新映射重解释旧符号。两种预览共同消费返回的文本及选项，最终由导入设置返回 `{ text, options }`，App 使用这一配对结果导入。目标符号或最短时值过粗而无法精确表示源时值时，提示至少所需几分音符并禁用确认；需改成足够细的时值，不能静默取整、丢符号或改变音长。

输出在原文中仅插入 `/`，音符、括号、原符号、空白、注释及原换行保留；首谱行不足全小节时另外在前方补显式休止形成弱起。若手填 `-` 为八分，则 4/4 的 `E-T-` 为 1 拍，前补 3 拍休止，下一行仍从正拍开始；不缩短首小节，不增加伪发声音符。支持一行确实包含多小节、跨拍/跨小节延音和独立的同音重触发；不齐行按原时间线连续并提示核对，不强补其他行静音。缺时值音和未映射符号显示原文行并阻止应用，原文可直接修正。数字谱的 `+/-` 可能是八度前缀，默认不自动当作时值；须明确勾选“将 + / - 用作时值（不用作八度）”后才采用这一含义。

原始行解释由 `SlashScoreOptions.sourceTimedRows` 与 `adjacentAsChord` 标记保存到 `@jpeditor` 元数据 `st` / `ac`，连同原符号映射及自身时值一起恢复。`projectSourceTimedRows` 将保留的正文投影到既有解析器可处理的内部时值表示，内部表示不替换用户原文；`parseSlashScore`、源码定位和诊断通过投影映射返回原文字位置。以原攻击时间线核对音高、起音与延音，保存重载不能因斜杠位置重新分摊或丢失原时值。末尾不足一拍仍补关闭斜杠，不添加时值；例如手工指定 `+` 四分、`-` 八分、`=` 十六分的 `A++++++++++++-=` 保持唯一攻击和完整 12.75 拍时长。

单个原符号的时值跨过拍界时，保留该符号，把斜杠提示放到它后面并显示警告；真实时间由原始行投影计算，不根据该提示位置重新分配音长。前置休止也只使用现有符号或自身时值表达；无法精确表示欠缺拍长时阻止应用，要求调整时值或手动补休止，不生成新的时值别名。

原始行解释保留隐形声部标记与 Unicode 字符的 UTF-16 源码定位。原文已有圆括号时当前只支持和弦解释，第二窗另选圆括号用途会明确报错；没有该括号时不受无关设置影响。谱面编辑生成普通斜杠正文后清除原始行标记，撤销从当前元数据恢复，不能沿用后来的解释模式。

最低回归为 `npm run check:add-slashes:unit`（根目录 `add-slashes-check.ts`）和构建后的 `node add-slashes-browser-check.mjs`。前者核对正文符号提取、空初始映射、一行一小节候选、原文保留、投影与元数据重载、起音、和弦、弱起、延音、第二步等长符号换写及过粗目标阻止；后者核对首次拍号自动填一次、手改保持、拍号提示与分析候选点击采用、两步确认、两窗简谱/文本谱同步预览、反复换写不累计、过粗目标提示、取消及原文编辑。改变既有 TXT 解析、源码定位或序列化时还需 `npm run check:slashscore`、`npm run check:source-mapping`。

### 已有斜杠文本的时值推断（2026-10-20）

没有保存过时值规则的TXT，按实际拍组中音符、圆括号和弦、空格及符号数量试算时值，优先匹配常用拍号。每行四拍、每拍四个音符/空格单位的文本可推荐4/4、音符自身与空格均十六分音符；原文没有时值符号时保持空映射，不补点号。实际出现的符号按节奏证据匹配，已有明确指令与保存选项保持原值。

新导入仅默认圆括号为和弦，其余括号留空，并对出现的括号提示填写用途。未配置的括号不参与时值推断，不默认解释为三连音；其原文和内部音符保留，诊断提示仍要求用户核对。没有可靠拍号时，导入窗拍数留空并禁止确认，填写有效拍号后才能继续。最多三种实际时值符号独立试算；不同候选即使拍长相同，内部起音不一致也需手动核对。新导入的未决时值符号必须逐个赋值，手填拍号不能绕过校验并把这些字符当注释忽略；已保存的空映射仍保持。右侧文本谱预览附行号，包含空行及末尾空行，复制文字不含行号。

最低回归：`npm run check:slash-import`；核心脚本支持追加本次十六分音符/空格谱样本路径验收完整文件，浏览器脚本可用`SLASH_IMPORT_FIXTURE`指定同一文件。单测和浏览器默认使用合成内容，不依赖用户电脑路径。另运行`check:slashscore`、`check:add-slashes:unit`与`add-slashes-browser-check.mjs`保护已有规则及两步换写流程。

### 整体内容缩放、音乐密度与页面水印

“排版→纸张与字号→整体内容缩放”滑块范围25%–200%，默认100%。保持所选纸张不变，标题、署名、歌词、速度、乐器名和全部音乐记号共同缩放并重新装行、分页，打印和页面导出使用这个比例。基础字号仍保存原始值，比例不会反复累乘；底部屏幕查看缩放独立。相关回归可单独运行 `npm run check:content-scale`。

排版设置中的“乐谱本体大小”默认约70.7%，简谱与五线谱共享此设置。它改变音乐字形测量、间距和装行，在A4页上容纳更多内容；标题、速度、调号说明、乐器名和歌词保留独立字号，底部预览缩放不参与此排版设置。简谱默认每行目标6小节，实际仍服从最小宽度和显式换行。五线谱音乐额外乘75%，谱表间距、刻度留位和谱行底部净空采用112/8/16的紧凑基准；普通密度每行约3–4小节、最多4小节，过密或显式换行提前装行。文字不乘额外75%，源正文、Score及所选纸张保持不变。

两谱面的刻度共用 `src/layout/rhythm-guide-style.ts`：主线深紫 `#6b4c8a`，短刻度从谱行下方向上指向音乐，描边至少 `0.7×contentScale`，避免紧凑五线谱的细线变浅。刻度只影响显示和输入命中，不修改音符时值；隐藏后仍可导航和输入。

纸张比例与方向同时作用于两种谱面，五线谱以 `pagePt × 96/72` 得到 CSS px 的页面尺寸，装行/分页、适应宽度和 PNG/PDF 使用同一纸张。A3 不再仍按固定 A4 绘制。钢琴简谱左侧占地由实测乐器名称、括号及净空计算，移除固定 68 单位空位，完整可见谱行的左右留白更均衡。

点击任一谱面的标题、副标题、作词、作曲或编曲，定位对应文字输入框，并逐项设置文档字号（8–144 pt，留空恢复默认）。`Score.headerTypography` 在 JPW `.Title` 的 `HeaderTypography` JSON 与 TXT v2 footer 的 `ht` 可选字段间往返；只保存显式覆盖，不自动改写旧文件。字体覆盖以 pt 保存，文字仅乘一次 `contentScale`，不再叠乘音乐密度或旧全局字号比例。两视图共享覆盖，缺失项各自沿用旧默认；文字与字号进入同一文档撤销事务，取消/换文档不提交。

页面导出按当前活动谱区提供PNG/PDF，简谱另提供矢量PPTX。选择格式后进入水印窗口，可开关水印、编辑文字和实时查看实际谱页；默认不透明度10%、每页7枚斜水印，中央完整、边缘可裁。取消不保存水印偏好，水印只写入导出副本。窗口另有“导出刻度线”复选框，每次打开默认关闭，确认后也不持久化；PNG、全页PNG/ZIP、光栅PDF及简谱PPTX统一使用此选项。预览与PNG/PDF共用 `composeExportPageSvg` 克隆合成，公开 `getPageExportSource()` 默认仍不含刻度；窗口显式请求 `includeRhythmGuides` 后按复选框筛选。五线谱通过独立页面渲染接口导出全部页面，不依赖当前挂载的虚拟页；选择/播放高亮、输入光标和悬停占位始终排除，屏幕SVG不变。

### 界面组织与设置

主界面名称为“原琴助手编辑器”，保留 Tauri identifier、文件关联、旧存储键和文档格式。
`src/bootstrap/workspace.ts` 负责菜单、工具栏、文本面板拖动及状态栏；`src/ui/theme.ts` 负责主题，
`src/ui/inspector.ts` 负责单个悬浮设置窗口与未应用修改提示；`src/ui/floating-window.ts` 管理拖动、缩放、边界与独立位置存储。新增组织逻辑不放进 App 的编辑算法。

`src/ui/app-dialog.ts` 统一异步输入、确认和消息提示，替代 `window.prompt/confirm/alert`；文件选择与打印仍走原平台入口。
输入窗口复用 `FloatingWindow` 的可选尺寸、居中与不持久化配置；乐谱/排版窗口的默认尺寸及存储规则不变。
同一时间只显示一个输入提示，背景暂时 `inert`，关闭恢复焦点及原状态；Enter/Escape、Tab 焦点循环和多行 Ctrl/Cmd+Enter 在窗口内处理。
输入通过校验并确认后才走原编辑事务；取消和文档替换不提交，跨 await 的模型修改同时检查 Score 身份。
设置点击背景时异步提供应用/放弃/继续编辑三种结果，渐快/渐慢的速度与终点合并填写。拖动/缩放不解析或序列化乐谱。

`editor/score-header.ts` 组织谱头输入，App 仅协调原文档事务；`editor:header-changed` 用局部字段同步已打开的乐谱设置，不覆盖其他分类草稿。
`editor/keyboard-note.ts` 提供三排琴键映射；直接改音只替换活动音符的源码跨度，保留时值、和弦其他音和隐形声部标记。
`ui/details-scroll-retention.ts` 在分类折叠前预留空间，完成展开/折叠后恢复原 scrollTop；空间只随上滚回收，关闭面板解除监听。
花括号新默认宽0.35×、粗3.2px，滑条分别为0.1–2×、0.1–5px；旧版更大的自定义值仍由归一化保留。延音/圆滑线默认厚度4→3.2，几何算法不变。

主题存储在 `jpeditor.ui.theme`，默认 `system`；新版布局状态沿用 `jpeditor-render-settings`，
增加 `workspaceLayoutVersion: 2`、`codePaneWidth`、`beatPositionFormat`、`showTextOnStartup` 和 `restoreLastFileOnStartup`。
旧版迁移默认左侧展开，启动默认载入内置键盘 TXT 示例；可在设置选择启动时隐藏文本或恢复上次文件。宽度/左右偏好持久化。以上设置不写入乐谱。

排版草稿使用 `App.setEngravingPreview`：只针对当前 Score 重新排版，保留 `.Layout` 断行设置，
不解析、不序列化、不写存储。200ms 连续修改只预览最后一份草稿；应用同步提交并保存，取消清除待执行预览后恢复。
`setEngravingStyle` 提交已保存值，文档语义设置仍通过原有撤销事务提交。
`ui/layout-preview-pane.ts` 在左栏切换文本/样张，保留 CodeMirror 实例；排版关闭后恢复原文。
`editor/shortcuts.ts` 定义与缓存场景快捷键，`ui/shortcut-settings.ts` 提供独立编辑窗口，偏好位于 `jpeditor.ui.shortcuts.v1`。
花括号使用 `layout/brace.ts` 的填充路径；`EngravingStyle.connectBarlines` 默认 false，由设置控制钢琴/总谱跨行连接。
打谱进入位置由 `input-entry.ts` 解析，`ScoreInputSession` 支持已启用但 cursor 为 null 的等待状态。

### 简谱／五线谱共享编辑（2026-10-10）

`src/staff-preview/` 直接读取已成功排版的简谱 `Score`，投影成独立模型并用 VexFlow 5 的 SVG 后端绘制。
投影不经过 MusicXML 导出再导入，不直接改写原模型；五线谱编辑通过共享编辑事务写回当前 JPW/TXT。与 `src/mixed/` 的独立 MusicXML 只读混排模型分开。
`model.ts` 处理音高拼写、声部时间线、补休止、三连音和跨小节拆分；`renderer.ts` 处理五线谱排版、系统模板缓存和 SVG，字体、导航索引及 SVG 辅助分别在 `renderer-fonts.ts`、`renderer-navigation.ts`、`renderer-svg.ts`；
`identity.ts`、`types.ts` 保存 `Note` 与 `{revision,id}` 引用；`controller.ts` 组织视图、导航、虚拟页、输入几何与异步任务；App 提供模型、编辑事务、选择、光标和播放桥接。

启动仍显示简谱；视图选项固定为简谱、五线谱、对照，直接显示用户选择的视图。谱区宽度不足 760px 时，对照临时切成单谱，恢复宽度再还原。
左右分栏比例保存在 `staff-preview-divider`，预览偏好保存在 `staff-preview-view`；文本面板保持原独立行为。
两个谱区分别滚动、分页和缩放，底部标明活动对象；首次生成适应五线谱可用宽度。关闭释放预览文档和已挂载页面，恢复简谱可见位置。

选择按当前版本的 `Note` 身份双向同步简谱、五线谱及文本；Ctrl/Cmd 点击切换单项。同音和弦、倚音和视觉续音不依靠音高字符串猜测。
五线谱获得焦点后使用 `staff-selection` / `staff-input` 快捷键上下文，定位另一侧不抢焦点；修改立即同步简谱及文本。普通模式从五线谱主选择播放，打谱中的 Space 仍前进。
五线谱上下键按当地调号移动一个书面位置；Ctrl/Cmd+Alt+上下移动半音，Ctrl/Cmd+上下移动八度，Alt+上下按绝对拍位移到相邻谱表。选择模式的数字 1–7 依次设全、二分、四分、八分、十六分、三十二分、六十四分，点号切换所选音附点；共享和弦时值只改一次，三连音按书面值与压缩值转换。N 打谱模式中数字、点号及顶部时值控件只设置待输入时值/附点，即使仍选中真实音也不改正文；TXT 沿用简谱格式的最细时值和附点限制。延音链同步改音，每段按当地调号重算简谱拼写；多选同链不会重复移动。
N 进入／退出打谱，Esc 退出；从选音进入时继承其谱表、拍位与书写音高。持久键盘光标使用金色列，悬停紫色列独立显示，不改变键盘位置；占位符头为实心浅紫 `#c9b6e4`，与已选真实音精确重合时保留深紫符头，不用浅紫占位覆盖。Enter 输入键盘占位，C–B（大小写）在当前拍位输入音名。无选音时音区取同谱表最近一次严格早于光标的攻击音／和弦平均书面位置，当前拍位新音及延音续段不参与；无前音时右手 C4、左手 C3。点五线／间输入，点刻度线仅定位；已有音仅在谱表、小节、拍位、MIDI 与书写 step/octave 完全相同时选择，否则按点击位置输入。点击、方向键和输入试听实际音高，悬停不试听；谱区不显示整块焦点框。右键经共享菜单编辑。共享 `buildRhythmGrid` 根据各视图实际 x 锚点生成自动／手动、附点和三连音刻度，隐藏刻度仍保留输入命中。
简谱多选进入打谱后保留多个 `InputTarget`，普通上下分别导航和弦层与虚线待输入位，Ctrl/Cmd+上下改变音区，Alt+上下跨谱行，1–7统一改音或填入占位。占位不选参照音；保存后按 part/measure/offset/tone/pitch occurrence 严格重绑，不用最近音补选。浅紫箭头按实际数字、八度点及减时线边界下移。
0 / Delete 按目标集合统一转休止；即使全部目标为 ghost，输入 0 也必须写回文档。只有明确 `sessionOnly` 的 ghost 音区/声部导航不保存音符。裸左右和 Space 沿主目标移动后结束旧多目标，Ctrl/Alt+左右仍采用主目标路径。
两谱面新起音经 `insertInputNoteWithDuration` 保留完整书写时值，跨小节建立延音并同步所有声部新增小节；遇到真实起音或不兼容三连音边界拒绝整批，不静默截短。五线谱右键提供七档时值和附点，Escape 关闭后恢复原谱区焦点。
多目标修改先解析独立草稿，全部操作、序列化及复解析验证成功后才提交一次文档事务；任何目标丢失、越界、冲突、三连音不兼容或格式无法表示均丢弃整批。撤销／重做同步恢复文档、选区和输入目标。
音级、音名、八度及五线谱调内/半音改音同样核对全谱独立起音和音尾。此类编辑序列化时保留全谱真实休止，包括未选小节的静默，避免把八分音符加八分休止写成长四分音符；仅编辑事务启用该保留覆盖，不改变用户的“保留0休止符”导出设置。`selection-shot.mjs` 覆盖两小节数字谱改音及八度、未选小节和导出偏好，`multi-input-check.ts` 覆盖音级、逐级、八度及音名四条共享路径。
临时升降号按简谱音级跨八度延续至小节末。整批改音后复用 `input-mode.ts` 的 `refreshInputAccidentals`，按受影响小节的真实音高重新设置必要还原号，包含延音链跨入的小节；普通音名、八度、五线谱改音及既有和弦/MIDI路径共享同一逻辑。例如G调首音改成B♭3后，后方原B4仍保持71，不能因省略还原号变成B♭4。`multi-input-check.ts` 与 `mobile-surface-modes-browser-check.mjs` 均检查未选音的音高和时钟。
播放事件沿用原播放器和反复 pass，两侧高亮；五线谱选择为深紫 `#75529e`，简谱沿用原选择颜色，播放为金色，两者重合保留紫色音头并加金色光圈。
手动滚轮、触屏、拖动滚动条或翻页只暂停该侧跟随，可用“恢复跟随”重启；新一轮播放恢复跟随，隐藏谱区不滚动，已可见音符不反复跳页。

VexFlow/渲染模块只在开启预览时动态加载，关闭状态不生成五线谱。更新按 200ms 合并，旧任务取消，并在异步结果接纳时复核 revision 和模型当前状态。
关闭时仅维护模型失效版本，不发送五线谱选区、播放和模型通知；开启时再读取当前选择与播放状态，避免给普通编辑增加后台更新。
锁定、待解析或失败期间，旧预览保留但不能选音；成功后才重新绑定引用。重排优先保留选音/播放的音乐位置，否则使用可见首音及其视口偏移。
页面只挂载可见范围及前后各一页的 SVG，系统几何模板按内容缓存；新快照即使复用图形也必须重新绑定当前 Note，不能沿用旧模型地址。
模板缓存同时包含谱行边界的调拍号、跳房子和远端连线信息，防止跨谱行改动沿用旧图形；打开另一文档立即释放旧页面和音乐位置锚点。
可访问状态用 `#staff-pane[data-staff-revision]` 表示最后成功版本，`aria-busy` 表示等待/生成；回归应等版本匹配且忙碌状态结束，不依赖中文提示。

当前入口仅支持单行与钢琴双行；多乐器总谱、识别视图和混排视图禁用并显示原因。支持音符/休止、和弦、谱号调拍、附点、三连音、延音/圆滑线、反复/房子、歌词、速度/文字及已映射装饰音。
这是普通 Score 的共享编辑视图，不承诺复现原始 MusicXML 出版布局；活动五线谱支持全部页面 PNG/PDF，踏板、力度渐变等未投影记号仍以原模型和原播放/导出为准。旧独立 mixed 视图不启用这些编辑命令。
无法精确表示的时值（当前最小 128 分音符）拒绝生成并保留上次预览；未映射装饰音、过密小节等显示诊断，不能静默改写原谱。
单小节超出纸张可用宽度时，按自然宽度绘制后整体缩小该谱行，并提示比例，保证尾部音符不会被纸张边缘裁掉；非二进制拍长的空隙保持精确时间间隔并提示未补写休止符。

## GitHub 发布

本项目的发布仓库为 `StarryCosmosPiano/genshin-jianpu-editor`，所有 `gh` 发布和工作流命令显式指定
`--repo StarryCosmosPiano/genshin-jianpu-editor`，避免被 `upstream` 远程影响。

从应用版本 0.4.0 起，使用 `yuanqin-v<版本>` 标签；仓库仍保留上游同名 `v0.4.x` 等历史标签，不移动或覆盖它们。
发布前先查询远端标签，确认新标签尚不存在；在验证完成的提交上创建并推送标签，使用
`gh release create <标签> --verify-tag --notes-file <说明文件> --repo StarryCosmosPiano/genshin-jianpu-editor`
创建发布。应用的 package、npm 锁文件、Tauri 配置、Cargo 包和锁文件版本保持一致。

`main` 推送部署在线版；Release 发布触发 Windows x64 和 macOS Apple Silicon 安装包构建。
检查工作流的提交与发布标签一致，并确认两个安装包均上传成功。核心回归必须只依赖已提交文件或内置样本；
本机私有曲谱不能成为 CI 必需条件。现有 `scripts/release.sh` 使用旧标签规则和 macOS 命令，不能直接用于此发布流程。

用户明确要求更新同一应用版本时，保留现有 Release，先完成验证并推送 `main`；仅更新该应用的 `yuanqin-v<版本>` 标签，并用远端旧标签对象的 `--force-with-lease` 防止覆盖他人的更新。随后手动运行 `Build` 工作流并传入 `release_tag`，工作流校验标签与应用版本一致、查找现有 Release，再构建并替换对应安装包；不会重新创建发布或覆盖说明。手动输入留空仍仅部署 Pages。安装包统一使用 `Yuanqin.Editor_[version]_[arch][setup][ext]` 文件名，保持同版本下载地址不变。

## 修改约定

- 工作区可能包含用户未提交改动，禁止用 `git reset --hard` 或覆盖无关文件。
- 文件按单个文件依次保存，避免一次机械重写多个核心文件。
- `src/jpword/parser/` 是生成代码，修改 `Jpwabc.g4` 后重新生成。

## 默认键位与原琴助手虚拟 MIDI（2026-10-22）

- 谱面默认 `Alt+↑/↓` 在简谱打谱中升降音级、五线谱打谱中升降半音；`Ctrl/Cmd+Alt+↑/↓` 在选择/打谱中移动声部或谱表。文本编辑器默认键位保持。已有自定义绑定按动作 ID 保留，未自定义默认键遇到冲突时让出，显式自定义冲突仍由设置检查。回归：`npm run check:shortcuts`、`node shortcut-preferences-check.mjs`、`node input-mode-check.mjs`。
- 原琴助手 1.8.2 自动创建的虚拟端点是一对 Loopback：助手发送到 `YuanQin MIDI Send`，编辑器应接收 `YuanQin MIDI Out`。系统枚举到端口、Host 进程存活或助手本地出声，都不等于已开启键盘外发。
- 电脑键盘外发需在原琴助手中开启映射，并将实际编辑器窗口所属程序选为目标。编辑器前台可打谱；在发送器窗口前台弹奏时，编辑器会记录到达的信号但暂停落谱。用设备设置窗口的按键计数区分路由问题和写入暂停。诊断不要直接重装驱动或修改系统兼容层。

## 虚拟 MIDI 输入端口识别（2026-10-30）

- `src/editor/midi-device-role.ts` 只按已验证的完整原琴端口名识别用途（忽略大小写及首尾空白）。Out 标为“原琴助手演奏输入”，Send 标为“原琴助手内部发送端”；一般硬件和其它虚拟设备即使带 In/Out/Return 也保持原名及可选性，不猜测方向。
- 两种传输共用设备选择界面：首次推荐 Out，其次普通输入，Send 排在最后且不默认推荐；已有选择仍存在时保留，包括手动选择 Send。只有 Send 时默认不连接，提供等待 Out 的提示；手动连接 Send 后状态栏明确指出接收演奏应选择 Out。推荐仅在打开设备窗口时选中选项，确认前不打开端口，不自动切换当前连接。
- `npm run check:midi:input:unit` 覆盖设备角色、枚举顺序及现有收信号状态机；构建后 `node midi-device-role-browser-check.mjs` 覆盖 Send 先枚举、Out 默认、真实输入事件落谱、普通设备/手选保留、仅 Send、热插拔及窄屏。既有 `node midi-entry-browser-check.mjs` 继续覆盖设备输入事务和暂停计数。
- 2026-10-30 本机 WinMM 实际枚举 Send/Out 均正常；用户从 Send 改选 Out 后确认弹奏可写谱。此结果证明当前虚拟链路可用，不代表 Windows 原生版编译或其它设备的硬件验收。
