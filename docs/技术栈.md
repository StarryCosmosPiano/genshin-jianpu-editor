# 技术框架与架构

## 技术选型

| 层 | 选型 |
|---|---|
| 桌面外壳 | Tauri 2 + Rust |
| 前端 | TypeScript + Vite |
| 文本编辑器 | CodeMirror 6 |
| JPW 语法 | ANTLR 4 + `antlr4` TypeScript 运行时 |
| 简谱渲染 | 原生 SVG DOM |
| 五线谱混排 | `src/mixed` 独立 MusicXML 模型 + SVG |
| 音乐字体 | Bravura（SMuFL）+ 系统中文字体 |
| 本地 OMR | PaddleOCR ONNX + `onnxruntime-web` / Tauri `ort` |
| PDF | pdf.js 输入，SVG→PDF 输出 |

## 运行时边界

前端 TypeScript 是应用主体，负责格式解析、Score 模型、排版、渲染、编辑、播放和大部分导出。
Rust 后端只承接浏览器无法稳定完成的桌面能力：Tauri 文件访问、SVG/PDF 处理、原生 ONNX OCR、
调用 `agy` 的 Gemini OMR，以及 macOS 原生 MIDI 播放。

MusicXML 的普通简谱导入和导出均位于前端：

- `src/score/musicxml.ts`：MusicXML → `Score`
- `src/score/musicxml-export.ts`：`Score` → MusicXML
- `src/mixed/`：保留 MusicXML 五线谱布局的独立混排路径

## 统一领域模型

```text
Score
└─ Part
   └─ Measure
      └─ Entry
         ├─ Chord
         │  └─ Note
         ├─ BarlineEntry
         └─ LineBreak
```

内部音符位置和时值使用 `Fraction`，统一以四分音符为单位。钢琴双手使用两个 `Part` 并设置
`score.piano`；多乐器总谱设置 `score.ensemble`，同一乐器内按 `Part.voiceIndex` 排序。

## 输入数据流

```text
.jpwabc
  → JpwFile → ANTLR → fromJpw ───────────┐

键盘谱/数字谱 TXT
  → parseSlashScore ─────────────────────┤

MIDI
  → parseMidi → analyzeMidi → midiToScore ┤

MusicXML
  → loadMusicXml ────────────────────────┤

ABC
  → abcToMusicXml → loadMusicXml ────────┤

图片/PDF
  → OMR → MusicXML → loadMusicXml ───────┤
                                          ↓
                                        Score
```

所有可编辑格式最终进入同一个 `Score`。`src/editor/document-parser.ts` 是 JPW/TXT 实时解析边界，
`src/editor/file-format.ts` 是文件扩展名、打开过滤器和保存格式的唯一注册表。

## 排版与渲染

```text
Score
 → Layout.fromScore()
 → 单谱行 / 钢琴双行 / 多乐器总谱
 → PageItem / Group / TextFrame / GraphicPath 页面树
 → JinpuPainter.renderPage()
 → SVG DOM
```

排版遵循“在哪测量就在哪绘制”：文字和路径在浏览器 SVG 中用 `getBBox()`、
`getComputedTextLength()` 测量，避免 Canvas、原生字体引擎和最终 SVG 产生尺寸偏差。

`src/layout/horizontal.ts` 是无 DOM 的横向排版核心：先建立共享节奏列，再计算小节最小宽度，
通过 water-filling 分配行宽，并按目标小节数贪心装入谱行。坐标只存在于当前排版树，不写入 JPW/TXT。

```text
src/
  bootstrap/  默认示例、拖拽、缩放等启动适配层
  common/     Fraction、几何、SVG 测量、资源路径
  smufl/      Bravura 元数据与字形码
  jpword/     JPW 分段、ANTLR 文法/生成代码、编辑器分词
  score/      Score 模型、JPW/MusicXML、时间线、MIDI 导出、时值编辑
  layout/     横向布局、分页、单谱/钢琴/总谱和 SVG painter
  editor/     App 控制器、文件格式、解析边界、对话框、选择、播放、导出
  slashscore/ 键盘谱/数字谱解析、声部、时值和互转

```

## 维护边界

- `src/main.ts` 只负责编排启动顺序；平台拖拽和缩放逻辑放在 `src/bootstrap/`。
- 文件扩展名不得在各模块重复写正则，应使用 `src/editor/file-format.ts`。
- 编辑器实时解析不得直接散落在 `App.reload()`，应通过 `src/editor/document-parser.ts`。
- `src/jpword/parser/` 是 ANTLR 生成代码，禁止手改。
- SMuFL PUA 码位使用 `String.fromCharCode(0x...)`，不要写字面 PUA 字符。
- 改排版后至少运行 `check:horizontal`、`check:piano` 和浏览器截图回归。
- 改文本谱、声部或时值后至少运行 `check:format`、`check:slashscore`、`check:selection`、`check:voice`。
